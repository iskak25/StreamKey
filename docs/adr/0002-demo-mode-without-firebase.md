# ADR-0002: Демо-режим без Firebase (открытый кабинет, хранилище в памяти)

Статус: принято владельцем продукта. Отступление от ТЗ (разделы 3, 4, 5, 13): Firebase Auth и Firestore не используются.

## Решение
- Если Firebase-учётные данные не заданы (или `DEMO_MODE=true`), приложение работает в демо-режиме:
  - хранилище — процесс в памяти (`src/lib/server/dev/memory-db.ts`), тот же API транзакций, что у Firestore;
  - входа нет: `/dashboard` открыт, действует фиксированный демо-пользователь;
  - секреты (CSRF, HMAC, receipt) при отсутствии переменных выводятся из публичной константы;
  - в интерфейсе постоянно виден баннер «Демо-режим».
- `DEMO_MODE=false` принудительно включает настоящий бэкенд (Firebase); тогда секреты и ключи обязательны.

## Последствия (известны и приняты)
- **Открытый кабинет:** любой, кто знает адрес, может создавать и отзывать ссылки. Авторизации организатора нет.
- **Нет общей памяти на Vercel:** серверные функции не делят состояние. Созданная ссылка может не найтись следующим запросом
  (другой экземпляр функции), данные пропадают при холодном старте и редеплое. Одноразовость и квоты в таком режиме не гарантируются.
- Публичные секреты означают, что подписи CSRF и сессий не защищают ничего.
- Не подходит для реального показа зрителям. Для production нужен постоянный бэкенд (Firebase по ТЗ либо Postgres) и вход организатора.

## Возврат к ТЗ
Задать `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `FIREBASE_PROJECT_ID`, `CSRF_SECRET`, `SESSION_HMAC_KEY_V1`, `RECEIPT_AES_KEY_V1`, `APP_ORIGIN`;
задеплоить rules/индексы; включить Google в Firebase Auth.
